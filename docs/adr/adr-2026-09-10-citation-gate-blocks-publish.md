# ADR: 出典検証（validate-citations.mjs）をビルド失敗条件にする／見出しは検証対象外とする

- 日付: 2026-09-10
- 状態: 確定

## Context

LLM が要約・生成する記事は、収集していない情報を「もっともらしく」書いてしまうリスク（ハルシネーション）が本質的にある。読み手が安心して読めることが本プロジェクトの核心要件であるため、公開前に機械的な裏取りが必要だった。

## Decision

1. 本文（地の文）の全ての文（句点・感嘆符・疑問符等で終わる一文単位）に、当日収集アーカイブ（`data/raw/<date>.json`）の実在する id を指す脚注 `[^s-<id>]` を必須とする。1件でも未解決・不正表記・無出典の文があれば `scripts/validate-citations.mjs` が exit 1 し、`daily.yml` は commit も Pages デプロイも行わない。
2. `##` 見出し（Stage A が生成する15字前後のテーマラベル）は検証対象から**意図的に除外**する。

## Rationale（2番目の決定について）

`codex review` の6回目のレビューで「見出し自体が暗黙の主張を含みうる（例:『AppleのAI攻勢と秋の新製品群』）のに脚注がない」という指摘を受けた。これは検討の上、意図的な設計として受け入れることにした:

- 見出しは Stage A が生成する**テーマの分類ラベル**であり、実際の事実主張は必ず直下の本文（Stage B が生成し、文単位で100%脚注を強制される段落）に書かれる。新聞・雑誌の見出しが個別に脚注を持たないのと同じ編集上の慣習に従う。
- 見出しの文字数制約（15字前後）上、脚注を複数付けるスペース的余裕がなく、無理に付けると可読性が落ちる。
- 見出しの「主張」は常に直後の本文で裏付けられる設計になっているため、実質的なハルシネーション遮断の効果は本文の文単位検証で担保されている。

## Consequences

- 見出し文言そのものが将来 LLM の暴走で明らかな誤情報を含むリスクはゼロではない。将来的に見出し生成プロンプトをより「中立的なラベル」に寄せる指示を追加する、または見出しと最初の文を結合して検証する等の改善余地は残る。
- 本文（実質的にすべての事実主張の所在地）は文単位で100%検証されており、AC-2 の「収集していない情報を書いたら公開しない」という核心要件は満たされている。
