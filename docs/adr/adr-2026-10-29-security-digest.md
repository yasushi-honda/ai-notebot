# ADR: 毎日のセキュリティニュース（セキュリティ版）の追加

- 日付: 2026-10-29
- ステータス: 採用（初版。対策・用語の「空率」は実データで測りながら拡張を判断する）

## 背景

2026年10月はセキュリティ事案が多く、「毎日のセキュリティニュースと、すぐできる対策・知っておくこと・用語集」を
これまでと同じ出典紐付けの形式で追加したいという要望があった。読者は一般の利用者・小規模事業者、範囲はセキュリティ全般
（AI 関連を含む）、用語集は「記事内＋累積ページ」で確定済み。

## 決定

### 1. 既存パイプラインをプロファイルの差し替えで再利用する（DRY）
AI版と同じ「収集 → テーマ分類（Stage A）→ 本文生成（Stage B）→ 出典ゲート」を使い、版ごとの違い
（ソース一覧・保存先・しきい値・プロンプト・スキーマ・frontmatter）だけを持つ。先に既存の版の挙動を変えない共通化
（PR #70: `lib/collect-core.mjs` / `lib/digest-curation.mjs` / `lib/orchestrate.mjs`、validate-citations の type 表、
サイトのパンくず・検証ラベル・ナビ）を行い、その上にセキュリティ版を足した。介護版のようなGoogle検索グラウンディングは
使わない（RSS で当日のニュースを拾え、出典 URL が安定するため。ただし RSS が網羅的である保証はない）。

### 2. 記事の形
`今日のトピック`（機械生成の表）→ テーマ3〜5本（何が起きたか／`### すぐできる対策`）→ `今日の用語`。hero 画像は作らない。
「知っておくこと」は独立した見出しにせず、本文に含める（見出しを増やすと、出典にない一般論で埋める失敗が出やすい。
PR #67 の監査で水増しを確認済み）。

### 3. 対策・用語は LLM に Markdown を書かせず、構造化して検証してから組み立てる
Stage B は `{bodyMarkdown, actions[], terms[]}` を返し、`lib/security-article.mjs` が個別に検証する。
- 対策: 読者が取れる行動だけ（運営会社・提供元側の対応は不可）、行動の形で終わる、引用 id がそのテーマの出典に限られる、
  構造を壊す文字を含まない。通らない項目は再生成ではなく除外（任意の内容のため）
- 用語: 引用した出典の title / summary に実在する語だけ、かつ記事本文にも出てくる語だけ。読みはひらがな・カタカナのみ
- 組み立て後の各行は句点の手前に脚注を置く（出典ゲートは句点までを1文とみなすため）。リスト行は
  `findUncitedListItems` で行単位にも検査する（句点の無い箇条書きは、1行にでも脚注があれば出典ゲートを通ってしまう
  ことを codex が再現した。ゲート自体は変えず、生成側で塞ぐ）
- 本文と frontmatter の `glossary` は同一データから生成し、書き出す前に `validateSecurityFrontmatter` で
  サイトのスキーマ（`content.config.ts`）への適合を検査する（違反したまま書くとサイト全体のビルドが落ちるため）

### 4. 失敗しても本体を止めない
`build-security.mjs`（`lib/orchestrate.mjs`）。失敗・時間超過（合計8分）で実行前の状態に復元して exit 0。
復元自体が失敗したときだけ exit 1。`daily.yml` では `security_exists` を posts / care と別に判定し、失敗は Issue で通知する。
`git add` は存在するパスだけ（初回生成失敗で本体のコミットが止まらないように）。

### 5. 固定の注意書きは出典ゲートの対象外（介護版の個人情報の注意書きと同じ例外）
記事ページの「ご利用にあたって」は LLM が生成しない人間が書いた固定文言で、事実の主張を含まない行動の案内
（公式情報で確認する）。脚注必須にすると、出典に由来しない案内を毎回出せなくなるため例外とする。

### 6. 情報源（2026-10-29 に取得確認）
JPCERT/CC・IPA・JVN・CISA Advisories（公的機関）、Security NEXT・ScanNetSecurity・piyolog（国内）、BleepingComputer・
The Hacker News（海外）。除外: Krebs（直近3日の新着なし）、NISC・ITmedia（item 0件）、CISA KEV JSON（RSS でなく巨大）。
RSS の要約が短い項目は、元ページの本文（`article`/`main` 優先、対策節を優先して最大1500字）で補う（`lib/article-text.mjs`、
SSRF 検査つきの `resolveSource` 経由）。

### 7. 外部由来のテキストの無害化（stored XSS 対策）
本文・見出し・出典タイトルは、外部フィード・外部ページの文章に影響される（プロンプトインジェクション）。Astro は Markdown 内の
生 HTML を通すため、次を入力側で塞ぐ。RSS のタイトルには CDATA・実体参照で生の `<script>` が実際に残ることを確認した。
- 本文: `findUnsafeMarkup` が `<strong>` 以外の HTML・画像・リンク記法・参照定義・URL を検出し、再生成させる（使い切ればテーマ除外）
- テーマ見出し: `sanitizeThemeTitle`（`<>` を全角に、表・見出しを壊す文字を除く）
- 脚注の出典タイトル・URL: `buildFootnoteDefs`（共通部品）で、タイトルの `<>[]` を全角に、URL の括弧・空白等をエンコード。
  AI版・介護版の脚注にも効く
- プロンプトでは、出典を `<source>` タグで隔離し、タグ内は指示でないと明示する（`formatIsolatedCandidates`）
`rehype-sanitize` の導入は、既存の版の表示（`<strong>`・介護版の要素）に影響しうるため見送った。
**AI版の本文（`curate.mjs`）には、本文の生 HTML を拒否する検査がまだ無い**（介護版にはある）。同じ経路の露出なので、
別途対応を検討する。

### 8. ページのデザイン: 「今日のポイント」パネルとカード化（2026-10-29 追加）
一般向けの毎日のニュースは拾い読みされるため、最初の5秒で「何が起き、何をすべきか」が分かる階層を作った。強弱は3段:
1) 最上部「今日のポイント」= ページで唯一のダーク（インク色）パネル、2) 各テーマ = 番号付きカード、3) 「すぐできる対策」= カード内の琥珀の囲み。
- **ポイントの内容は検証済みの文の再掲だけ**: テーマごとの見出し1文（Stage B の `headline`、長さ・禁止文字・文の区切り・URL/HTML・引用 id を個別に検証、
  通らなければそのテーマはポイントに載せない）と、検証済みの対策（各テーマの先頭1件、最大4件）。新しい主張を LLM に自由に書かせない。
  テーマは Stage A に「読者への影響が大きく緊急性の高い順」と指示して並べる（順序は機械では検証できない）
- **本文の Markdown に HTML ラッパーを書かない**: 出典ゲートは HTML のブロック行を脚注のない文として落とすため。h2 ごとの
  `<section class="sec sec-…">` は描画時に `site/src/lib/rehype-security-sections.mjs`（security の記事だけが対象）で付ける
- 「今日のトピック」の表は、英単語の長いセルでモバイルの横幅を超えるため、セキュリティ版だけセル内で折り返す（AI版・介護版の表は未対応のまま）

## 却下・見送った案
- 公式の対策節・用語解説を別途収集してアーカイブする工程（codex 提案）: 初版では入れない。実記事で対策・用語の空率を測ってから判断する
- 同一 URL の更新（注意喚起への追記）の再採用: 既存の既出 URL 除外をそのまま使う。更新を取りこぼしたと分かった時点で追加する
- 週刊まとめへのセキュリティ版の組み込み、Cloud Scheduler の変更（`daily.yml` 内のステップ追加で足りる）

## 実データでの確認（2026-10-29）
- 収集: 9ソース全て取得、51件（要約が短い27件を本文の抜粋で補強）。生成 約10秒。出典検証は裏取り率100%
- 別モデル（Sonnet）による出典忠実性の監査（18文）: OK 11 / 拡張 4（軽微）/ ずれ 3（軽微）。数値・固有名詞の誤りや捏造は 0。
  ずれは「複数の事案を1文に並べて主語・確度が混ざる」「件数を『多数』とまとめる」で、プロンプトに対策を追加した
- 検証の効果: 実記事で、運営会社側の対応（読者が取れない）、行動の形でない文、本文に出ない用語、製品名の用語を除外・再生成

## 既知の限界と、次に見るもの
- 対策は出典に書かれたものだけなので、ニュース記事中心の日は空になりやすい（初回実データ: 4テーマに対策1〜4件）。
  用語も同様に少ない。実運用で空率を見て、公式資料の補助取得を検討する
- 出典ゲートは脚注の実在と文ごとの有無を見るだけで、意味の忠実性（定義・対策が出典の内容と合うか）は保証しない
- しきい値（5ソース・20件・時間予算8分）は暫定値。休日を含む数日分の実データで見直す
- 用語集の同じ用語は、最も新しい記事の定義を載せる（定義が変わりうる）
- 再生成を使い切って除外したテーマの出典は、収集のアーカイブには入っているため7日間は既出扱いになり、翌日以降の記事にも載らない
  （AI版と同じ設計。セキュリティ版では重要な情報を取りこぼしうる）。除外は `::warning::` で見える
- 劣化（対策が全て空、補強の成功が半分未満、公的機関の項目が0件、テーマ除外）は Issue ではなく Actions のアノテーション
  （`::warning::`）で通知する。記事ファイルが無い「全滅」だけが Issue になる
- `curate-weekly.mjs` の Stage A/B の重複は今回も解消していない（次に週刊を触るときの候補）
