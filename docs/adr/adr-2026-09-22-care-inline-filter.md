# ADR: 介護AIハックのカテゴリ絞り込みをCSSの:has()による同一画面内フィルターにする

- 日付: 2026-09-22
- 状態: 確定

## Context

PR #32 で介護AIハックに `workArea`（業務領域）・`targetServices`（対象サービス）の静的カテゴリ
ページを追加し、`/care/` トップの冒頭に「業務領域から探す →」「対象サービスから探す →」の
2リンクを置いた。これに対し decision-maker から明確な却下があった:

> ここはせっかくのタグなんですから、ユーザーに画面遷移をさせるべきではなくて、もっと同じ
> 画面内でもっと直感的にフィルターできるようにすべきです。

このプロジェクトは Astro 7 + Tailwind CSS v4 の静的サイトで、UIフレームワーク統合
（React/Vue等）が無く `client:*` は使えない。手書きクライアントJSの前例は
`posts/[date]/index.astro` のコピーボタン1箇所のみだった。

## Decision

### 絞り込み自体はCSSの`:has()`セレクタで行い、JSは強化層に留める

チップの実体はネイティブ `<input type="radio">` + `<label>`（各軸内は単一選択の
radiogroup）。`/care/index.astro` のビルド時frontmatterで、実データから
「あるチップがcheckedのとき、対応しないdata属性を持つ`<li>`を`display:none`にする」
という規則をenum値の数だけ機械的にCSSルールとして生成し、`<style set:html={...}>`で
埋め込む。ページ全体を1つの`#care-content`でラップし、`:has()`はDOMの入れ子構造に
関係なく「配下のどこかに対象がある」ことだけを見るため、`role="radiogroup"`等の
正しいa11yセマンティクスのための入れ子（`<fieldset><legend>`）と両立できる。

JavaScriptは以下の強化のみを担当し、**フィルタリングの成否には関与しない**:
- 他軸の選択を固定した上での各チップの動的件数再計算・0件チップの無効化
- URL同期（`history.replaceState`、フィルタ用3キー以外は保持）
- `aria-live`によるライブリージョン通知
- クエリパラメータからの初期状態復元（deep link）

### 採用しなかった代替案: `<a href>`をJSがクリックを奪ってその場でフィルタする方式

初期実装ではチップを既存の静的カテゴリページへの`<a href>`にし、JSが`preventDefault()`
してその場で絞り込み、JS無効時は従来通り画面遷移するプログレッシブエンハンスメントを
採用していた。しかしセカンドオピニオン（Planエージェント）のレビューで、**JS無効時の
フォールバックが「画面遷移する」であり、decision-makerが明示的に拒否した挙動そのもの**
という設計思想上の欠陥を指摘され、この案を破棄した。`:has()`方式はJSが完全に無効でも
同一画面内フィルタが動作するため、この欠陥を構造的に解消する。

### 「全サービス共通」の包含規則

`targetServices`の値「全サービス共通」はワイルドカードではなく他の値と対等な独立した
enum値だが、実運用上は「どのサービス種別でも使える」という意味のため、具体サービスで
絞り込んだ際もこの値を持つ記事を含める。このロジックは3箇所（`src/lib/care.ts`の
`matchesTargetService`・CSS生成・クライアントscript）に分散するため、値を変更する際は
3箇所とも同期させる必要がある（`src/lib/care.ts`のコメントに明記）。

### 単一選択・3軸・0件チップ無効化はdecision-maker自身が選択

AskUserQuestionで以下を確認済み: フィルタ軸は業務領域・対象サービス・導入の手間の3軸、
既存の静的カテゴリページは残す（SEO・deep link用）、軸内は単一選択、0件になるチップは
件数を動的に無効化する。

## Consequences

- 新規記事追加時、CSSルールはビルド時に実データから再生成されるため追加のメンテナンスは
  不要（enum値が増えた場合も自動的にチップとルールが増える）
- `difficulty`用の静的カテゴリページは意図的に作らなかった（分布が9/4で`/care/`トップと
  ほぼ同一内容のnear-duplicateページになり、pagefind索引・sitemapを汚染するため）。
  詳細ページの「導入の手間」ピルは`/care/?difficulty=X`というJS依存のdeep linkで、
  JS無効環境ではこのリンクだけ絞り込みが効かず全件表示になる既知のトレードオフ
  （対象・業務領域のピルは専用静的ページへのリンクのためJS有無に関わらず絞り込まれる）
- 3軸フルセットは記事13件の現状では機能するが、フィルタ状態空間の約半数が0件組み合わせに
  なる（実測45.8%）。0件チップの動的無効化で行き止まりは防いでいるが、記事が数十件規模に
  増えた場合はUIの再評価が必要になる可能性がある
